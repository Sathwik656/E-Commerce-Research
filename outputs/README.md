# Research Outputs

Unified Olist pipeline. All artifacts here are generated by:

- `python prepare_data.py` — builds the shared datasets under `data/`
- `python train_churn.py` — churn tables/figures (`churn_*.csv`, `churn_*.png`)
- `python train_spending.py` — spending tables/figures (`spending_*.csv`,
  `spending_*.png`), `dataset_summary.csv`, `experiment_configuration.json`,
  `customer_risk_value_examples.csv`, `model_metrics_comparison.png`

Both models use the **same source (Olist) and the same customer population**
(repeat customers, i.e. >= 2 delivered orders). Monetary values are in
**BRL (Brazilian Real)**. Raw customer identifiers are not published in any
output here.

## Design at a glance

| | Churn model | Spending model |
|---|---|---|
| Source | Olist delivered orders | Olist delivered orders |
| Population | repeat customers as of a snapshot | repeat-customer order events |
| Features | RFM + basket/freight/installments/recency/tenure (pre-snapshot) | prior-order history only |
| Target | no order within 150 days after the snapshot | payment value of the next order (conditional on it existing) |
| Split | out-of-time: train 2018-01-01 snapshot, test 2018-04-01 snapshot | out-of-time: orders before vs after 2018-01-01 |

## Notes

- Churn is evaluated out-of-time on a later snapshot never seen in training.
- The spending evaluation set contains only orders placed after the split date;
  each observation predicts the spending of the customer's next order,
  **conditional on a subsequent order existing**.
- Churn is a rare-event target (~96% of repeat customers do not buy within 150
  days), so accuracy is dominated by the majority class; **ROC-AUC / PR-AUC**
  are the informative metrics.
- `model_metrics_comparison.png` labels the two panels separately; churn
  classification scores and spending regression errors must not be compared
  as if they measured the same quantity.
